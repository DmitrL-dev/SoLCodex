# Quiet diagnostic measurement-path qualification: development matrix

**Status: partial development matrix; no model run authorized.** The [expected outcomes](data/2026-09-25-quiet-measurement-qualification-expectations.json) are for synthetic, no-model probes of trace adherence, ledger reconciliation and fake-success rejection. They do not qualify the full transport, evaluator, reducer, environment or future held-out experiment. The [exposed four-run screen](../measurements/2026-09-25-quiet-diagnostic-model-screen-development.md) remains failed.

An Astra reviewer read only the [prospective protocol](2026-09-25-heldout-quiet-screen-proposal.md), without implementation, prior tests or probe outputs, and independently specified the expected classes. The reviewer later clarified two ambiguous cases: a byte-identical repeated CLI `item.completed` is `unknown` without proof of benign replay; a recorded terminal signal exit `-9` is `violated` when the expected baseline exit is `1`. The exploratory probe was constructed and first run while the blind review was in progress. Thus this matrix is a development qualification aid, not a prospectively blinded validation result.

For the first diagnostic, `observed` means the assigned command, expected exit and complete event order are proven; `violated` means a different command, early action, interruption or wrong baseline exit is proven; `unknown` means the evidence is incomplete or malformed. Only `observed` can pass the adherence gate. A duplicate completion, missing ID, malformed JSON, error item, missing terminal event or lost beginning is `unknown`. Normal assistant text is not a tool action. A later whole-run timeout may leave an already completed first diagnostic `observed`; its checkpoint and usage still require separate evidence.

The ledger cases require a late provider completion after client disconnect to count once. Missing, partial, pending or mismatched usage must leave reconciliation incomplete with usage `null`. Provider billing remains separately unverified. A printed `PASS` is rejected by the host's structured verifier boundary; this direct probe alone does not test behavioral repair acceptance or evidence tampering.

Before admitting any new model task, run the frozen matrix against the exact future code and archive hashes of the parser, transport, reducer, evaluator, fixtures and results. Add end-to-end synthetic disconnect/retry, timeout and source-checkpoint cases; verify the exact CLI version and complete provider attempt ledger; independently review the outcomes. Any unknown status blocks promotion. The private runner and evaluator assets currently limit external reproduction, so a passing direct probe cannot be used as a general savings or quality claim.
