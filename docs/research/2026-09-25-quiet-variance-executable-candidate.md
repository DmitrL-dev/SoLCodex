# Executable candidate for exposed quiet-diagnostic variance calibration

**Status: candidate, with model execution forbidden.** The [candidate protocol](../measurements/data/2026-09-25-quiet-variance-calibration-candidate.json) pins the existing [16-slot schedule](data/2026-09-25-quiet-variance-calibration-schedule.json), 13 harness source files, CLI/model settings, exposed source trees, regression patches, attempt ledger, Python test runtime, and evaluator assets. The [runner snapshot](../measurements/fixtures/2026-09-25-quiet-variance-calibration-runner.py) validates the pushed protocol and schedule. It explicitly refuses `--execute` while `model_run_authorized=false`. The [public audit](../../scripts/audit_quiet_variance_candidate.py) recomputes the schedule, visible pins, and closed qualification state without the private harness; private code bytes need separate verification.

The proposed campaign executes one four-run block per invocation. An append-only, fsynced private journal records each slot's launch intent before `one_live` can contact the provider, then hashes of its host files, ledgers, checkpoint tree, evaluator report, and admission result. The parent directory is synced before any launch. A dangling launch intent, missing or changed evidence, unknown usage or quality, or unknown/violated first diagnostic prevents automatic retry and further launches. A known quality failure remains an admitted observation with its full token cost; a timeout may continue only with complete accounting, verified cleanup and checkpoint, known quality, and an observed first diagnostic. Pins are checked before and after each slot. A crash after launch needs manual forensic reconciliation; the runner never grants a fresh 600-second window to the same slot.

Only two of five listed qualification artifacts are currently available: the direct parser/ledger matrix and the late-missing-usage negative control. The current positive-path CLI check was exploratory; the integrated checkpoint control uses older source hashes; independent review of the complete path remains open. These are marked `null` in the candidate protocol. Even after those artifacts exist, their coverage and exact source hashes must be reviewed before producing any launch-authorized revision. The current runner verifies evidence file hashes, not semantic sufficiency of a future review. The existing four-run screen remains failed and is excluded from this calibration.

Astra's read-only code review found that a power loss could drop the campaign directory entry and that resume originally checked only `final.json`. Both were corrected before this candidate was committed. Local no-model checks verified directory `fsync` support, rejection of a dangling launch, and rejection of changed trace, ledger, checkpoint, and evaluator evidence. A physical power-loss recovery test has not been performed.

The private runner and evaluator assets limit external replay. The Python environment currently has no symlinks; the runner rejects any that appear because a symlink target would otherwise fall outside the runtime digest. The host OS and native libraries are not frozen by this hash. The present harness starts its 600-second shared deadline before sandbox canaries, so available CLI time can be slightly shorter; this needs to be quantified and fixed or explicitly accepted before model launch. Provider-attempt tokens include cached input in input, but provider billing is not independently verified. The remaining weekly model quota has not been shown sufficient for a complete four-run block, so no block is started under this candidate.
