# Python quiet diagnostic 24-task selector (proposed)

**Status: scoped selector implemented; approvals pending; no real sample selected.** This [dedicated selector](../../scripts/select_quiet_python_sample.py) uses the frozen Python-only pool of 7,124 tasks across 687 direct repository names. It retains the quiet-screen quota of eight tasks in each of `state`, `build`, and `api`, at most one task per independently reviewed lineage. The broader confirmation corpus and its 120-per-family selector are unchanged.

The CLI takes the private projection, full lineage map, ancestry evidence, lineage ranking and complete task review. Before selection it validates the projection against the [published aggregate](../measurements/data/2026-09-25-quiet-python-projection.json), verifies the [scoped ancestry approval](data/2026-09-25-quiet-python-lineage-map-approval.json) against current code and global development exposure, and **replays the entire lineage ranking** from those inputs. The submitted ranking must equal that replay exactly. It then checks a separate [sample approval](data/2026-09-25-quiet-python-sample-approval.json) binding the precise bytes of every private input, both approval and aggregate files, this rule and the normative [screen proposal](2026-09-25-heldout-quiet-screen-proposal.md), the selector and shared matching code, plus two distinct independent task curators. Both approvals remain pending. A locally edited `approved` value is not evidence that an approval appeared in public Git; the coordinator must verify the committed manifests before running the CLI.

Curators independently classify **every task in every visited eligible lineage** in committed rank order, without seeing arm assignment, model outcomes, remaining quotas or rank order. The review is the complete contiguous prefix through the first feasible assignment of eight lineages to each family. Qualification requires the environment, independent behavior oracle, collection-preservation checks and wrong-fix controls in the [screen proposal](2026-09-25-heldout-quiet-screen-proposal.md). Unknown or disputed tasks are excluded before assignment with the recorded reason. The shared deterministic maximum-cardinality matcher assigns at most one task per lineage, then takes the lowest task rank eligible for its family. Any review change requires a new approval and complete replay before the first arm; no substitution follows the first arm.

The output is a private mode `0600` no-replace file; stdout contains counts only. Selection alone does not authorize a model run. The 24 identities, environments, oracles, schedule, provider accounting, and quality gates must be frozen and separately qualified before the first treatment or control run. The older [full-corpus quiet selector](2026-09-25-quiet-screen-selector.md) remains a separate pending path and cannot be used as approval for this Python pool.
