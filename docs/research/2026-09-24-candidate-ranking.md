# Metadata-only candidate ranking gate (2026-09-24)

**Status: preparation, not selection.** The [confirmation draft](2026-09-24-confirmation-campaign-draft.md) calls for a once-only candidate pool across independent repository lineages. During source inspection, the Hugging Face dataset page displayed six preview rows with snippets of `patch` and `test_patch`. All six repository lineages were immediately moved into the development exposure list. No task IDs have been selected for confirmation, and no outcome from a remaining eligible lineage has been inspected for this gate.

The [development exposure list](data/2026-09-24-development-exposure.json) is public before any ranked selection. It excludes SoL Codex, Click, packaging, SQLGlot, and SymPy lineages previously used in development, six preview lineages from [SWE-rebench V2](https://huggingface.co/datasets/nebius/SWE-rebench-V2), and four codebases consulted during research. The dataset card shows that rows contain `patch`, `test_patch`, and test lists. Those fields must remain outside the ranking input. The exposure list is a minimum: unknown forks and project continuations still require independent curator review.

[`scripts/rank_confirm_candidates.py`](../../scripts/rank_confirm_candidates.py) accepts only `instance_id`, `repo`, `language`, and `license` in private JSONL. It enforces narrow identifier and metadata formats; any extra field, including gold or test content, fails the whole run. It normalizes GitHub repository names, rejects duplicate logical repository issues, excludes the directly exposed repositories, and sorts the rest by `SHA256("solcodex-confirm-2026-09-24-v1\n" + instance_id)`. Input, export manifest, and output must be outside the public repository on a POSIX host; existing output cannot be overwritten. The output includes input and exposure hashes and marks every remaining lineage as **unreviewed**. This is a schema and ordering gate, not proof of independent ancestry or task eligibility.

[`scripts/export_swe_rebench_metadata.py`](../../scripts/export_swe_rebench_metadata.py) is the next gate. Its CLI hardcodes the dataset, revision `475dd5e8703bb5fb22dd3c60b5d038b019eba1e0`, train Parquet file, and a four-column SQL projection. DuckDB's [HTTP range reads and Parquet projection](https://duckdb.org/docs/current/core_extensions/httpfs/https) allow it to avoid downloading the outcome-bearing columns. A synthetic Parquet test confirms that `patch` and `test_patch` do not enter the exported JSONL. The real pinned export has **not yet been run**. A fresh private runtime directory prevents reused DuckDB state. Metadata and manifest use atomic no-replace publication, and the manifest's content hash binds the pair. The exporter records row count, projected file hash, code hash, and DuckDB version in a private manifest; ranking verifies these fields against the full 32,079 rows. This is reproducibility metadata, not an independently signed origin attestation. Then two curators must review licenses, repository ancestry, issue quality, runnable images, and independent verifiers. Do not publish ranked IDs until the once-only analysis. Selection remains NO-GO until the isolation and complete request-accounting gates in the confirmation draft pass.
