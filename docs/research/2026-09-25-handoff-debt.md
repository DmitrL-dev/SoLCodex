# Handoff debt and the phase-reset hypothesis (2026-09-25)

[KC and Budathoki, *Handoff Debt*, v2](https://arxiv.org/html/2606.02875) study coding-agent takeovers from frozen repository checkpoints. Their main study starts with 75 SWE-bench Verified source tasks, creates 181 handoff points, and compares four views for each of three successor models: repository only, a textual raw trace, free-form summary notes, and structured notes. The resulting 2,172 takeover runs are correlated within source task; they are not 2,172 independent defects. The authors report that context-bearing views use 42–63% fewer cumulative **successor prompt tokens** and 20–59% fewer median successor agent events than repository-only takeover, depending on model and view. Official solved-rate differences are smaller and vary by model and handoff state.

This comparison supports carrying useful diagnosis evidence forward. It does **not** establish our proposed Codex phase reset saving: the paper's reference is a new successor with only the repository, whereas our OFF arm resumes the original Codex session with its native history and cache. Its “raw trace” is text supplied to a new successor, not a native session resume. The reported successor prompt-token metric excludes the model calls that generate summary and structured-note fields; completion tokens, wall time, and GPU-hours are not part of the cross-view cost result. Therefore the headline reductions cannot be transferred to full-task provider tokens, billed cost, or latency for SoL Codex. These boundaries are explicit in the paper's [experimental design and reproducibility details](https://arxiv.org/html/2606.02875#S4) and [Appendix B](https://arxiv.org/html/2606.02875#Sx2).

The paper's own failure analysis finds compact notes can omit the exact validation command or warning, and successors can over-trust a predecessor's interpretation. A raw trace can instead burden the successor with irrelevant history. Its [structured handoff schema](https://arxiv.org/html/2606.02875#Sx3) separates deterministic checkpoint and validation fields from model-written understanding, uncertainty and next steps. That is a useful *design candidate*, not a proven optimal format: some note-based solved-rate slices are negative relative to repository only.

The authors' [reference code](https://github.com/anjilab/agent-handoff-debt) includes the harness and selected task identifiers but states that raw trajectories, Docker workspaces, model-server logs and full experiment outputs are absent. The published numeric result would require rerunning that environment for independent reproduction. We have not rerun it.

## Consequences for our next test

- Compare a **fresh Codex session with a bounded handoff** against native `codex exec resume` from the same diagnosis checkpoint. A repository-only fresh session can be an additional mechanism control; it must not replace native resume as the economy baseline.
- Freeze the stop rule and handoff schema before model work. Record the exact validation command and result, relevant source locations, evidence versus hypotheses, uncertainty, and next verification step. Normalize workspace paths without rewriting technical evidence. The successor should verify handoff claims against the checkpoint.
- Count diagnosis, handoff generation, all continuation requests including retries and late completions, cached and uncached input, output, and elapsed time. A shared diagnosis is counted in each potential deployment policy total; actual experimental spend is reported separately. Evaluate both complete source checkpoints externally and blind to arm.
- Keep repetitions within one repository lineage clustered. The [old exposed packaging pair](../measurements/2026-09-24-phase-reset-development.md) saved 20.0% in CLI-reported input-plus-output but increased uncached input and time, and lacked complete provider accounting. The [synthetic transport probe](../measurements/2026-09-25-phase-reset-transport-exploratory.md) fixed the session-isolation design only. Neither supports an economy or quality claim.

An Astra design review of the proposed 2–3-lineage development A/B identified five launch gates: fixed diagnosis/handoff policy, equal branch state and isolation, balanced order with lineage-level analysis, frozen complete provider accounting, and independently qualified external quality checks. No real-model phase-reset A/B has passed these gates. The review recommended prioritizing the simpler native quiet-diagnostic hypothesis for the next development screen; its [previous four-run screen](../measurements/2026-09-25-quiet-diagnostic-model-screen-development.md) failed quality and first-command audit gates, so a new screen also requires corrected measurement qualification and new prospective tasks. This is an experiment-order decision, not evidence that quiet diagnostics save tokens or preserve quality.
