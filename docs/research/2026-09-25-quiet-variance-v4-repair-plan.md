# v4 calibration repair plan (development, not frozen)

The [independent v3 audit](../measurements/2026-09-25-quiet-variance-bundle-v3-independent-audit.md) rejected authorization of the 16 model runs. The v3 candidate remains pending and unchanged. This note records the next protocol revision under development; it does not authorize model calls.

The revised campaign coordinator must write a durable `start` before each launch. A started slot is never retried. It must seal hashes of all available host evidence even when the checkpoint, final result, or quality report is missing, then write one terminal `finish` with `continue`, `stop`, or `complete`. A pre-start pin failure writes `stopped` without consuming a slot. The journal supplies ordered `unstarted_ids`; an unclosed `start` stays unresolved and cannot be resumed as a new run. Ordinary quality failure and a timeout with complete usage remain observations. Accounting, cleanup, checkpoint, adherence, or quality uncertainty stops subsequent launches. A broken seal or journal blocks automatic continuation.

The v4 protocol will pin both the copied virtual environment and the base Python executable, tree, and loaded module origins. It will check those pins before and after every slot. The OS and external toolchain remain outside that runtime freeze and must be reported as a limitation.

The draft [analysis reducer](../../scripts/reduce_quiet_variance_calibration_v4.py) takes a redacted 16-slot JSON export pinned to the existing schedule. Its [checks](../../scripts/test_reduce_quiet_variance_calibration_v4.py) cover a failed repair, an accounted timeout, zero accepted repairs, a stopped slot with known or unknown usage, a pre-start stop, an unresolved start, and invalid assignments or counts. For a complete campaign, it reports all-started input, cached input and output, tokens and elapsed time per accepted repair, eight paired differences and ratios, acceptance discordance, dispersion by task, and first-arm/first-task order strata. For an incomplete campaign, it reports known upstream lower bounds and incomplete usage IDs without a treatment estimate. The reducer verifies arithmetic and schedule consistency; it does not authenticate provider usage or evaluator artifacts on its own.

The development export now distinguishes `verified_complete`, `lower_bound`, `unknown`, and `not_started` usage states. `usage` is populated only for verified complete accounting; `known_upstream_usage` retains a validated lower bound for stopped or unresolved slots. The reducer sums each slot's known amount once and leaves `all_started_usage` null while any started slot lacks verified complete accounting. It never estimates a treatment effect from an incomplete campaign. Every started export row carries an accounting evidence hash, and the export carries protocol and schedule hashes. The reducer checks their form and the schedule match; independent review must still authenticate them against sealed host evidence and the frozen protocol.

The private coordinator prototype has no-model controls for foreign final attribution, absent or malformed final evidence, missing ledgers, pending and late upstream completions, WAL sidecars, quality failure, cleanup uncertainty, restart, and tampered seals. A lower bound from a WAL snapshot remains incomplete even if all currently visible attempts are completed. Full accounting requires the sealed final/result identity, matching source artifact hashes and ledgers, closed broker and bridge, no active handlers, and a reconciled upstream total. These controls are development evidence only; the v4 campaign-path qualification result and independent review are still absent.

An independent red-team pass on the mutable v4 draft found gaps in the seal's read consistency, request-to-ledger identity, cleanup admission, quality-report evidence binding, deeply nested final handling, unresolved usage classification, and campaign-path qualification. Local no-model regression controls now exercise the first six findings. The runner deliberately rejects a filled `campaign_path` evidence slot until a frozen machine verifier checks its content. This is a development stop gate, not a qualification decision; the revised bytes still need prospective control evidence and independent re-review.

Before a new candidate can be frozen, a prospective no-model control must exercise the **actual** campaign coordinator, including quality failure followed by another launch, cleanup/accounting failure with terminal stop and exact unstarted IDs, missing or malformed final evidence, pin drift, interruption after durable start, restart after durable finish, and tampered seals. The new candidate must pin the coordinator, export logic, reducer, base Python contract, and control result. Independent re-review must accept those exact bytes before any model request. The 16 runs, if later authorized and completed, would calibrate variability on two exposed tasks; they would not establish general SoL Codex savings.
