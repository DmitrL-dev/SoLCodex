# Quiet diagnostic 24-task selector (proposed)

**Status: code proposed for review; approvals pending; no task selected.** This is the dedicated selection rule for the [24-lineage held-out screen](2026-09-25-heldout-quiet-screen-proposal.md). It reuses the reviewed maximum-cardinality matching algorithm but fixes the quota at eight tasks in each of `state`, `build`, and `api`. It is separate from the 120-per-family confirmation selector and its approval.

The input pool is the previously pinned SWE-rebench V2 revision `475dd5e8703bb5fb22dd3c60b5d038b019eba1e0`. Before this selector can write a private result, the current lineage-map approval must match the ranking, exposure manifest and ranker hashes. A separate [quiet-screen sample approval](data/2026-09-25-quiet-screen-sample-approval.json) must bind the exact private lineage ranking and complete task-review bytes, this rule document, the dedicated wrapper, shared matching code and metadata helper, and two distinct independent curators. Names in JSON are attestations; the underlying review records must also be audited. Both approval manifests are pending.

The selector validates the submitted ranking's shape and order, but does not reconstruct its ranks, exposure witnesses or completeness from the source corpus. Before approval, independent reviewers must replay the candidate ranking and lineage-map stages against their pinned source and exposure inputs and audit the complete private review records. The approval hash then binds the exact submitted ranking bytes. The CLI reads local approval files; a local `approved` value alone does not prove those files were published. The coordinator must verify both approved manifests in a public Git commit before running this CLI.

The coordinator reviews lineages in committed rank order. Exposed lineages are recorded and skipped. For every visited eligible lineage, both curators classify **every** candidate task before its lineage enters the matching. The reviewed entries form the complete contiguous prefix through the first point at which eight lineages can be assigned to each family. A task is eligible only after license, historical environment, independent defect witness, preservation checks and the six qualified wrong-fix controls in the screen proposal are complete. Unknown or disputed quality excludes it before any arm; record the reason and preserve review history. Curators must not see arm assignment, model outcomes, remaining family quotas or rank order while judging a candidate.

The selector assigns at most one task per lineage using the shared deterministic capacity matching, then picks the lowest task rank eligible for the assigned family. If any pre-arm qualification changes a classification, the private review and approval hashes must be revised and the same frozen selector replayed from the beginning. No substitution is allowed after the first arm. Selected identities stay private until the once-only analysis. The output prints only counts, records its inputs and selector hashes, and explicitly does not authorize a model run. A successful selection still needs frozen environments, oracles, transport, assignment schedule and the campaign gates.
