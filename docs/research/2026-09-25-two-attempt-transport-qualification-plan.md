# Two-attempt synthetic transport qualification: development matrix

**Status: development matrix; no model run authorized.** The [expected outcomes](data/2026-09-25-two-attempt-transport-expectations.json) cover a no-model run through the loopback sidecar, host bridge, two attempt ledgers, CLI trace auditor and source checkpoint. A synthetic credential and provider stub are used; no actual provider or billing system is contacted. This is a transport and accounting check, not a repair-quality or token-savings experiment.

An Astra reviewer read only the [held-out proposal](2026-09-25-heldout-quiet-screen-proposal.md) and [unit-qualification plan](2026-09-25-quiet-measurement-qualification-plan.md), without code or existing tests. The reviewer independently specified two attempts with input `120 + 200 = 320`, cached input `40 + 150 = 190` (included in input), and output `30 + 50 = 80`. The positive case must count both provider completions once, including an undelivered first response. The negative case with missing first-attempt usage must leave complete-run usage `null`; the second attempt's `200` input and `50` output are only a partial subtotal. The fixture was being implemented while the blind review ran, and exploratory executions occurred before this public freeze. It is not a prospectively blinded validation result.

Delivery has two layers. A disconnected CLI client can leave the broker-to-CLI delivery failed while the host bridge successfully streams to the broker. The broker's failed delivery and the provider's completed execution must remain attached to the same attempt ID. The second attempt must have a different ID and complete delivery. A recorded provider completion with missing usage is `unknown` for accounting even though the provider event reports completion.

For future screens, use the already [published exposed-protocol wall-time convention](2026-09-25-quiet-diagnostic-model-screen-protocol.md): start at CLI launch and end after upstream attempts finish or the shared deadline closes them; report CLI completion time separately. This resolves an ambiguity the reviewer identified in the new proposal. The synthetic fixture must prove the first provider completion follows CLI termination and that elapsed run time includes it.

The fixture uses a fake evaluator result to keep this probe free of real model and independent repair calls. A captured, unchanged source tree and exact first diagnostic do not qualify repair acceptance. Provider billing also remains unverified. Before any held-out model launch, the full parser, transport, reducer, evaluator, environment and synthetic fixtures still need frozen hashes and independent qualification.
