# Two instruction-blinded SymPy repairs (exposed development task, 2026-09-24)

After the [diagnostic mutation pilot](2026-09-24-sympy-diagnostic-mutants-development.md), two separate child agents were given identical issue-level instructions and different clean exports of SymPy #26807 parent `530149c`. The prompt described `lambdify(ArraySymbol('a', (3,)), a, 'numpy')` recursing instead of returning an input NumPy array by identity. It named each designated source checkout and a Python runtime, but withheld the historical fix, the earlier 35-check verifier, the later 37-check verifier, and the mutation results. Each agent was instructed to inspect only its own checkout. The two source exports initially matched the pinned 2,061-file parent digest.

Both agents independently inserted the same line, `_iterable = False`, immediately inside the shared `_ArrayExpr` class. Their source file hashes are identical (`32baae5ef099a8e48e7f5c2675cb076646160844a41e944197133a4dedd158bc`). One agent also added a focused `lambdify` test; the other changed only the source file. Both reported successful issue-specific tests. An inspection of their app command histories found 22 and 13 command executions, all with the designated checkout as working directory and none explicitly referencing the gold tree, either hidden verifier, the SoLCodex repository, or a network command. This is an **instruction and observed-command audit**, not enforced filesystem isolation or proof that no inaccessible context influenced either agent. The task was already exposed in development and potentially in model training.

Only their identical source change was copied onto a fresh parent export for external evaluation. The self-written test and interpreter caches were excluded. The clean replay export digest is `7b2229e7abc672e53057d748ad5c28330ccf417a1239a56a30409c5cf88f0914`. The external checks used the earlier macOS arm64 / Python 3.12.13 environment with NumPy 1.26.4, mpmath 1.3.0, pytest 8.2.2, and Hypothesis 6.108.8.
