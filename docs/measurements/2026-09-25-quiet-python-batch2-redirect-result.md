# Second-batch redirect destinations: four-target capture

The [follow-up plan and controller](../research/2026-09-25-quiet-python-batch2-redirect-plan.md) were pushed in commit `5f2b333` before any destination request. Five redirects in the [second 40-name batch](2026-09-25-quiet-python-repository-batch2.md) pointed to four distinct GitHub numeric repository endpoints. The controller made exactly four serial requests, one per endpoint, with no automatic redirect. All four returned `200` with valid repository metadata and an ID equal to the requested numeric endpoint. The journal has one durable start and result per request, and the run ended `pilot_complete`.

The [published aggregate](data/2026-09-25-quiet-python-batch2-redirect-result.json) records the queue, source-journal, destination-journal and controller hashes plus fixed counts. All four responses reported `fork=false` and no `parent` or `source` fields. The private queue and response journal remain mode `0600`; no repository names, task IDs, patches or raw response bodies are published.

This captures direct metadata or explicit redirect-destination metadata for the contiguous first **60 of 687** projected Python repository names. It does not establish that differently named repositories are independent, or that five old names mapping to four destinations represent only four project lineages. The remaining 627 names lack this capture, and two independent curators still need to assess forks, mirrors, migrations, common upstreams and development-exposure links before the [lineage map approval](../research/data/2026-09-25-quiet-python-lineage-map-approval.json). No task selection or model run is authorized.
