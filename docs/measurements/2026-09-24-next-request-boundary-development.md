# Next model request after a PreToolUse rewrite (2026-09-24)

Four isolated development runs tested a **temporary probe plugin**, not the installed SoL Codex hook. Each asked `codex-cli 0.155.0-alpha.16.3` to run `cat payload.txt` once. The file held 8,000 ordinary bytes plus a fresh random `HIDDEN_` marker that was absent from the prompt. Direct runs executed `cat` normally. In PreToolUse runs, the temporary hook replaced it **before execution** with a helper that ran `cat` once, wrote its exact output to a private artifact, and returned a 29-byte status without the marker. The test was repeated with code mode disabled and enabled.

An instrumented local HTTP model route forwarded the two observed POSTs per run to the fixed ChatGPT backend, evaluated marker membership **in memory**, and discarded request bodies and authorization values. Both responses completed in each run. The [fixed-field aggregate](data/2026-09-24-next-request-boundary-dev.json), generated by the [audit script](../../scripts/audit_prehook_request_probe.py), retains only marker booleans, sizes, usage fields from completed responses, and hashes of private traces and proxy summaries.

| Mode | Command | CLI tool-result bytes | Marker in second model request | Second request body bytes | Second response input tokens |
| --- | --- | ---: | --- | ---: | ---: |
| Direct | `cat` | 8,033 | Yes | 60,374 | 11,091 |
| Direct | PreToolUse helper | 29 | No | 52,295 | 10,059 |
| Code | `cat` | 8,033 | Yes | 56,376 | 10,589 |
| Code | PreToolUse helper | 29 | No | 52,296 | 10,062 |

In both helper runs the private artifact contained the original bytes and marker; the first model request contained no marker. The direct runs' second requests did contain it. This is stronger evidence of the **observed next-request boundary** than the model's final answer alone. It covers one simple command on this host. The model answered with the marker after direct execution and `UNKNOWN` after the helper, so the task behavior was deliberately different.

The displayed input-token differences are descriptive request observations, **not** a task-level saving: cache states, execution order, and outputs differed. A CONNECT count is not a provider request count; this probe's two completed HTTP responses are narrower evidence, still not an independent bill. The temporary plugin had four blocked non-model connections in each hook run, so this is not an inventory of all attempted network traffic. The custom HTTP route disabled WebSockets and retries and logged a model-list refresh error; ordinary transport was not tested. Enabling code mode did not prove that a JavaScript `await` consumed this tool result.

The probe did not test nonzero status, shell syntax, stdin, signals, disk failure, conflicting hooks, cache pruning, or repair quality. The temporary helper merged output into an artifact and did not establish transparent shell semantics. An installed opt-in implementation needs a separate strict admission policy and failure contract before an ON/OFF repair experiment. The current [hook boundary study](../research/2026-09-24-hook-result-boundary.md) still applies to SoL Codex's `PostToolUse` receipt.
