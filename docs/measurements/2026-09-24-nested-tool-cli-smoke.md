# Target-CLI nested-tool smoke (2026-09-24)

The [protocol](../../experiments/action_fusion/nested_smoke/protocol.json) and exact [valid](../../experiments/action_fusion/nested_smoke/valid_prompt.txt) and [invalid](../../experiments/action_fusion/nested_smoke/invalid_prompt.txt) prompts were frozen in commit `269e38a6709094b3027ce297c447692f1de5a4a2` before either model call. This exposed-fixture development check used Codex CLI `0.155.0-alpha.16.3`, `gpt-6-luna` at low reasoning, code mode, and two isolated one-shot runs. The patch was supplied in each prompt. The invalid patch targeted a nonexistent line.

The valid run produced one completed file-change item, then one completed command item running only `python3 -m unittest discover -s tests -v` under the CLI shell wrapper. Its published [source snapshot](../../experiments/action_fusion/nested_smoke/results/valid/duration.py) has the frozen gold SHA-256 `9896aa3d83c745a7e91c32256cfe1c4cdd93a89c6a14c0268ca8ecb267cdc26f`. The public verifier passed 4/4 and the independently isolated external verifier passed 34/34. The invalid run reported `apply_patch verification failed`, produced no completed file-change or command item, and left the source at the parent SHA-256 `cba812ea43e3005bc1937a88d5696bdcbb6ef011c4e6ea11589651cd7ee8f0b2`. These observations verify the edit/test sequence and the failure gate for these two prompts.

Both runs had two completed model requests with proxy-observed usage and no unknown attempts. The valid run recorded 20,270 input and 374 output tokens; the invalid run recorded 19,863 input and 234 output tokens. The runs have different tasks, so these figures are **not** a saving estimate. The isolation canaries passed, agent authentication was absent, observer errors were zero, and process-group cleanup completed. Provider billing completeness was unavailable.

The provider stream showed one outer `custom_tool_call` in each arm but supplied no caller IDs linking nested patch and verifier items to it. The CLI trace exposed the file-change and command items without their outer caller. The stricter one-program nested attribution criterion is therefore **INCONCLUSIVE**. Approval policy was `never`, so separate approval decisions remain **NOT TESTED**. No independent repair A/B or general efficiency claim follows from this smoke.

The fixed-field [aggregate](data/2026-09-24-nested-tool-cli-smoke.json) was generated by the [reducer](../../experiments/action_fusion/nested_smoke/reduce.py), which checks the frozen hashes, source and trace shapes, request usage, evaluator controls, and failure gate. Raw model traces and authentication remain private. The [Linux Docker replay](../../experiments/action_fusion/nested_smoke/replay_behavior.py) independently reruns the published source against all 34 cases in the pinned image; its CI result is separate evidence of behavior, not tool-call attribution.
