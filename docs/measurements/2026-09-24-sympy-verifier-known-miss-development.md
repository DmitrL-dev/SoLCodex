# SymPy verifier known-miss probe (exposed development task, 2026-09-24)

The original frozen verifier for [SymPy #26807](https://github.com/sympy/sympy/issues/26807) scored both agent repairs 35/35. Later review found that both placed `_iterable = False` on the shared `_ArrayExpr` superclass, changing `ZeroArray` and `OneArray` behavior. The augmented verifier adds two compatibility checks for those classes. This probe reproduces that **source-level** variant from the historical parent, then tests a different local fix that does not copy the gold line. The v2 checks were written after the agent outcomes. Their status as acceptance requirements is [unresolved](2026-09-24-sympy-contract-reassessment.md), so the score difference is not a demonstrated mutation kill.

| Source tree | Frozen v1 | Post-hoc v2 | Same selected upstream tests |
| --- | ---: | ---: | ---: |
| Parent `530149c` | 18/35 | 20/37 | 48/48 |
| Historical fix `6760ace` | 35/35 | 37/37 | 48/48 |
| Shared-superclass edit from parent | **35/35** | **35/37** | 48/48 |
| Alternative `ArraySymbol` property from parent | 35/35 | 37/37 | 48/48 |

The shared-superclass edit adds only `_iterable = False` to `_ArrayExpr`. V1 scores it 35/35; v2 fails exactly `C19_zero_array_iterable_preserved` and `C20_one_array_iterable_preserved`. The alternative adds an `ArraySymbol._iterable` property returning `False`; both verifier versions and the upstream selection score it fully passing. These are finite behavioral checks, not proof that either repair is fully correct. The 24 pinned upstream node specifications resolve to 48 test cases in this environment and do not distinguish the superclass variant.

The [public experiment code](../../experiments/sympy_26807/README.md) includes byte-identical copies of v1 and v2, the pinned upstream selection and its resolved 48-test inventory, a one-file source-variant materializer, an upstream runner, and a [fixed-field reducer](../../experiments/sympy_26807/reduce_qualification.py). The [aggregate](data/2026-09-24-sympy-verifier-known-miss-dev.json) records complete source-export, verifier, private report, JUnit, selection, and resolved-inventory hashes, all eight verifier scores, exact failed assertion IDs, and negative qualification flags. The reducer checks the parent and gold export digests, compares every other file in each variant to the parent, binds reports to source and verifier hashes, requires exact expected failure reasons, and rejects a substituted upstream test. The runner removes inherited pytest switches and overrides project `addopts`; a deliberately supplied deselection option was ignored in a fresh probe, which still ran the pinned 48 tests. Private raw reports contain local paths and detailed exceptions and are not published. The public code and pinned Git revisions permit a fresh reproduction, subject to reproducing the environment and checkout exports; the stored raw reports cannot be independently audited without access to them.

This probe used macOS arm64, Python 3.12.13, NumPy 1.26.4, mpmath 1.3.0, pytest 8.2.2, and Hypothesis 6.108.8. The original agent pair used a different Python micro-version. The test does not qualify the requested Linux worker, the proposed six plausible wrong fixes per task, an alternative-fix diversity gate across tasks, independent reviewers, or any SoL token-saving claim. It shows that a verifier can pass the parent/fix preflight and several mutations yet still omit a neighboring behavior change; whether that change is damaging needs independent API-contract evidence.

A later [six-variant diagnostic pilot](2026-09-24-sympy-diagnostic-mutants-development.md) measured five more source edits against v2. They were chosen after v2 was visible; several are derivative or have disputed acceptability. The six-plausible-wrong-fix gate remains open.
