# Action-fusion mechanism pilot

This exposed synthetic development fixture tests one instruction from the [efficient-agent-loop skill](../../plugins/sol-codex/skills/efficient-agent-loop/SKILL.md): after an agent knows both an edit and its narrow verifier, can it execute both in one programmatic tool call while preserving their separate statuses? The [protocol](protocol.json) freezes one OFF → ON pair before model runs. OFF may fuse naturally; ON receives only the additional [fusion instruction](on_instruction.txt). Both receive the same [task prompt](base_prompt.txt). Hooks, receipts, other skills, delegation, and phase reset are disabled. The [public fixture](fixture) is copied into separate isolated workspaces, and the [external verifier](external_verify.py) stays outside the agent workspace.

Before model execution, the parent failed the public and external checks. A private reference fix passed all four public and 34 external cases. Eleven constructed wrong variants and one test-runner forgery variant failed the external verifier; two variants share a whitespace witness. These source variants are targeted development controls, not independently sourced plausible repairs. Their [source files](controls) and [hash/witness manifest](controls_manifest.json) were published after the model pair; the raw model, reference, and mutation logs remain private. The private runner and its dependencies are pinned in the protocol. A dry run confirmed the parent failed the public tests, code mode was enabled, and the agent sandbox could read its workspace while denying the reference, host artifacts, and host authentication. A separate network-denied evaluator passed the reference and rejected the parent. Its trusted controller compares the 34 results outside the candidate process. The tested profile denies candidate writes to the evidence directory, loopback connections, `fork`, and `posix_spawn`; each child runs in its own cleaned process group. A forced timeout and attempted background spawn both left no running process in that group.

The [development result](../../docs/measurements/2026-09-24-action-fusion-mechanism-development.md) publishes the fixed-field [aggregate](../../docs/measurements/data/2026-09-24-action-fusion-mechanism-dev.json), [OFF and ON source snapshots](results), and an independent [Linux Docker behavior replay](replay_behavior.py). The replay checks all 34 cases for the parent, reference, and both candidates; it checks one pinned failing witness for each constructed wrong variant. Run it with `python3 -m experiments.action_fusion.replay_behavior` on Linux x86-64 with Docker Engine. The [reducer](reduce_pilot.py) checks the private model, proxy, and evaluator artifacts against the frozen protocol; it needs the private run roots and does not publish raw traces or authentication.

The pilot measures completed model requests, proxy-observed tokens, tool calls, elapsed time, and external behavior. A missing usage record remains unknown, and no arm is rerun for a cleaner record. This one fixed-order task cannot establish a quality floor, a general saving, provider billing, or the effect of the installed SoL Codex hook.
