# Action-fusion mechanism pilot

This exposed synthetic development fixture tests one instruction from the [efficient-agent-loop skill](../../plugins/sol-codex/skills/efficient-agent-loop/SKILL.md): after an agent knows both an edit and its narrow verifier, can it execute both in one programmatic tool call while preserving their separate statuses? The [protocol](protocol.json) freezes one OFF → ON pair before model runs. OFF may fuse naturally; ON receives only the additional [fusion instruction](on_instruction.txt). Both receive the same [task prompt](base_prompt.txt). Hooks, receipts, other skills, delegation, and phase reset are disabled. The [public fixture](fixture) is copied into separate isolated workspaces, and the [external verifier](external_verify.py) stays outside the agent workspace.

Before model execution, the parent failed the public and external checks. A private reference fix passed all four public and 34 external cases. Eleven constructed wrong variants and one test-runner forgery variant failed the external verifier; two variants share a whitespace witness. These source variants are targeted development controls, not independently sourced plausible repairs. Their source and report hashes are pinned in the protocol; the raw reference and mutation logs remain private until after the model pair. The private runner and its dependencies are pinned there as well. A dry run confirmed the parent failed the public tests, code mode was enabled, and the agent sandbox could read its workspace while denying the reference, host artifacts, and host authentication. A separate network-denied evaluator passed the reference and rejected the parent. Its trusted controller compares the 34 results outside the candidate process. The tested profile denies candidate writes to the evidence directory, loopback connections, `fork`, and `posix_spawn`; each child runs in its own cleaned process group. A forced timeout and attempted background spawn both left no running process in that group.

The pilot is designed to measure completed model requests, proxy-observed tokens, tool calls, elapsed time, and external behavior. The model route uses a local host-only broker; raw traces and authentication are kept private. A missing usage record remains unknown, and no arm is rerun for a cleaner record. This one fixed-order task can check whether fusion happens and whether its model-turn effect is worth a broader experiment. It cannot establish a quality floor, a general saving, provider billing, or the effect of the installed SoL Codex hook.
