# Target-CLI nested-tool smoke

This is an exposed-fixture development check of whether Codex CLI code mode can execute a patch tool and a verifier tool from one model-authored program, with a failed patch stopping before the verifier. It does not compare repair quality or estimate savings. The parent, public tests, and 34-case external verifier are the frozen action-fusion fixture in the parent directory.

The [valid](valid_prompt.txt) and [invalid](invalid_prompt.txt) prompts supply exact patches. Separate isolated runs use `gpt-6-luna` at low reasoning with code mode enabled, hooks/plugins/skills disabled, and the same 240-second limit. The private runner, dependency hashes, prompt hashes, CLI version, and run order are locked in [protocol.json](protocol.json) before model execution. Raw model traces and authentication remain private; published results will contain only fixed-field aggregates and source hashes.

Acceptance for this technical smoke requires the valid run to show one outer program call with a separately attributable patch item followed by one verifier item and a 34/34 source, and the invalid run to show a failed patch with no verifier item and an unchanged source. Attribution must use response caller IDs or equivalent direct tool metadata, not prompt text or timing. Missing caller data, incomplete usage, a second repair attempt, or any failed containment control makes the mechanism inconclusive; shell edit-plus-test fails the mechanism. Separate approval decisions and a general efficiency effect are outside this no-approval development runner.

The [result note](../../../docs/measurements/2026-09-24-nested-tool-cli-smoke.md), [fixed-field aggregate](../../../docs/measurements/data/2026-09-24-nested-tool-cli-smoke.json), [reducer](reduce.py), and [Linux behavior replay](replay_behavior.py) document the completed one-shot runs and their attribution limit.
