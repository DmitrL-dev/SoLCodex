# SoL Codex

SoL Codex — локальный плагин для Codex Desktop. Он архивирует подходящий крупный вывод инструментов, запрашивает ограниченную квитанцию без отклонения вызова и отслеживает проверки изменений кода. Это независимая адаптация идей SoL для системы хуков Codex.

Плагин может менять вывод прямого вызова, видимый модели, а в режиме `bypassPermissions` оборачивает распознанные команды проверки для записи их кода завершения. В code mode скрипт всё ещё может получить исходный результат вложенного вызова. Плагин не выбирает модель, не запускает compaction, не вызывает другую модель и не обещает экономии токенов, денег, квоты или времени.

## Быстрый старт

Нужны Codex с поддержкой плагинов и хуков и Python 3.9 или новее (`python3` на macOS/Linux, `py -3` или `python` на Windows). Контракт хуков проверен на Codex `0.155.0-alpha.9.2`.

```bash
codex plugin marketplace add DmitrL-dev/SoLCodex
codex plugin add sol-codex@sol-codex
```

Откройте `/hooks`, проверьте разрешённые команды и подтвердите доверие к плагину, когда Codex запросит его. В сборках Codex с горячим обновлением хуков новая версия может подхватиться в той же задаче; проверьте это реальным событием хука. Постоянный загрузчик также восстанавливает инициализированную задачу после очистки старого кеша. Ограничения и обновление описаны в [инструкции](docs/installation.md).

## Что делает плагин

- `PostToolUse` обрабатывает результаты shell-команд и патчей. Подходящий извлечённый текст больше 6 KiB сохраняется в `PLUGIN_DATA`; для `gpt-6-astra` порог равен 4 KiB. Для структурированного результата артефакт содержит извлечённый текст, а не побайтовую копию всего объекта ответа.
- Прямой результат может быть заменён ограниченной квитанцией со статусом (либо `unknown`), хешами, диагностическими строками и коротким preview. В code mode исходный вложенный результат может сохраниться. Редактирование секретов в квитанции работает по известным шаблонам; полный локальный артефакт не редактируется.
- Успешное изменение кода создаёт verification debt. Распознанная команда снимает его только если соответствующий `PreToolUse` сработал после последнего изменения кода, а структурированный статус или приватный status-файл подтвердил код завершения 0.
- `PreCompact`, `PostCompact` и `SessionStart` сохраняют напоминание после compaction. `Stop` предупреждает о невыполненной или неуспешной проверке, не блокируя ответ; агент обязан честно сообщить статус проверок.
- Закреплённый загрузчик сохраняет вызванный runtime в `PLUGIN_DATA`: после очистки старого кеша инициализированная задача продолжает работать, а обновлённый корень хука может выбрать новую версию в той же задаче.
- По каждой модели считаются агрегированные байты исходного вывода, квитанции и их потенциальной разницы. Эти числа не измеряют вход модели в code mode, токены, стоимость, квоту, задержку или качество.

Строковый результат `PostToolUse` может получить квитанцию, если до хука дошло достаточно байтов, но в ней будет `exit_code=unknown`, если статус не пришёл из sidecar проверки. `PreToolUse` записывает поколение изменений кода для распознанной проверки. На macOS/Linux в режиме `bypassPermissions` он дополнительно оборачивает распознанные Bash-проверки для фиксации статуса; на Windows и в режимах с подтверждениями он не переписывает команды. Структурированный результат может передать статус напрямую. Хост может обрезать вывод до вызова хука. Начиная с 0.1.9 хук использует `continue: false` вместо `decision: block`, поэтому не отклоняет Promise после выполнения команды. Текущий хост code mode всё ещё может передать скрипту исходный результат; для гарантированно короткого вложенного ответа нужен явный адаптер.

Схема и точная последовательность событий приведены в [описании архитектуры](docs/architecture.md).

## Настройка порогов

Переменные нужно задать до запуска Codex:

```bash
export SOL_CODEX_ASTRA_PACK_THRESHOLD_BYTES=4096
export SOL_CODEX_PACK_THRESHOLD_BYTES=6144
```

`SOL_CODEX_ASTRA_PACK_THRESHOLD_BYTES` действует только для уже активной `gpt-6-astra`. `SOL_CODEX_PACK_THRESHOLD_BYTES` — глобальное переопределение с более высоким приоритетом. Значения задаются в байтах и ограничиваются снизу числом 256. Плагин не выбирает модель: Astra-профиль включается только когда Codex уже передал `gpt-6-astra` как текущую модель.

## Отчёт

В [обзоре исследований экономии контекста](docs/research/2026-09-23-context-efficiency.md) собраны близкие работы и порядок проверок. Обзор не меняет выпущенный плагин и не переносит на него результаты чужих экспериментов.

[Разбор Unreal Agent](docs/research/2026-09-24-unreal-agent.md) сверяет заявленную разницу в стоимости 39,23% с опубликованным запуском Harbor и отделяет асинхронное управление циклом агента от механизма квитанций этого плагина.

[Разбор RRSI](docs/research/2026-09-24-rrsi.md) добавляет защиту от подгонки харнесса под повторно используемые задачи: учёт опровергнутых гипотез, заморозку независимой выборки и сравнение полной стоимости с исходной системой. Экономия токенов в статье измерена относительно другой эволюционировавшей системы, а не SoL Codex.

[Исследование цены восстановления свидетельств](docs/research/2026-09-24-retrieval-economics.md) разбирает новые работы по памяти агентов и проверяет, может ли агент найти важную строку вне короткой квитанции. Качество, токены, повторное чтение и время учитываются отдельно.

[Прототип ограниченного поиска по артефакту](docs/measurements/receipt-adapter.md#bounded-artifact-search) не даёт широкому буквальному запросу вывести весь сохранённый лог. Это отдельный экспериментальный инструмент, он не входит в установленный плагин.

[Разработочная A/B-пара](docs/measurements/2026-09-24-bounded-search-development.md) прошла проверки исправления и израсходовала меньше суммарных токенов и времени на одной ранее использованной задаче. [Протокол подтверждения](docs/research/2026-09-24-cost-frontier.md) задаёт независимые задачи и критерии, необходимые для вывода об устойчивой экономии.

[Разработочная пара по безопасности кеша](docs/measurements/2026-09-24-cache-boundary-development.md) прошла обе проверки на другом дефекте: суммарных токенов меньше на 10,3%, время больше на 19,7%. Это разведочный результат, а не доказательство экономии денег или общего выигрыша.

[Разработочная пара на историческом CRLF-дефекте](docs/measurements/2026-09-24-historical-crlf-development.md) выявила пробел в проверке: оба исправления провалили полную матрицу стилей строк исходника и запуска, хотя ON прошёл первоначальную узкую проверку. ON израсходовал на 31,8% больше токенов. Полная матрица добавлена к регрессионным проверкам и критериям приёмки будущих задач.

[Проба изоляции на macOS](docs/measurements/2026-09-24-agent-isolation-probe.md) нашла способ закрыть агенту доступ к рабочему репозиторию с будущим исправлением в исторических экспериментах. Перед подтверждающей серией нужно проверить ограничения для остальных файлов и платформ.

[Исследование границы результата хука](docs/research/2026-09-24-hook-result-boundary.md) описывает ограничение code mode, уже сделанную upstream работу и изменение 0.1.9, сохраняющее выполнение цепочки вызовов.

[Исследование обновления хука в существующей задаче](docs/research/2026-09-24-live-hook-refresh.md) фиксирует успешное обновление на следующем turn той же задачи без перезапуска приложения. Code-mode-скрипт всё ещё получил исходный результат.

[Разработочная проба HTTP-прокси](docs/measurements/2026-09-24-http-proxy-usage-development.md) получила финальный `usage` через 12,352 секунды после убийства CLI. Отдельный прототип журнала попыток прошёл проверку перезапуском; он пока не подключён к прокси и не сверялся со списаниями провайдера.

[Пилот на настоящем репозитории](docs/measurements/2026-09-24-real-repo-pilot.md) содержит две парные задачи, агрегированные данные и описание невалидных проб. Обе пары прошли независимые проверки; влияние на токены и время зависело от задачи.

[Разработочные прогоны на исторических задачах](docs/measurements/2026-09-24-natural-history-development.md) показали, что ON-агенты Click и packaging ни разу не вызвали адаптер и потратили больше токенов, хотя прошли внешние проверки. В первой паре SQLGlot OFF завершилась по таймауту без данных о токенах; во второй паре с полной телеметрией OFF прошла 13/13, а ON остановилась без исправления. Экономия от сжатия и снижение стоимости не доказаны.

В отдельной [разработочной паре SymPy](docs/measurements/2026-09-24-natural-history-development.md#sympy-arraysymbol-apparent-token-reduction-post-hoc-regression) обе руки сначала прошли 35/35 внешних и 48/48 выбранных upstream проверок. С адаптером provider-токенов было на 31,8% меньше, а времени ушло на 5,4% больше, но дополнительная проверка после прогона нашла одинаковую регрессию `ZeroArray`/`OneArray` в обоих исправлениях. Это пробел в verifier, а не принятый результат об экономии.

[Руководство по учёту A/B-трасс](docs/measurements/ab-trace.md) описывает агрегирующий парсер `codex exec --json`, приватный манифест, проверку качества и ограничения прежнего пилота из пяти пар.

[Прототип явной квитанции для команды](docs/measurements/receipt-adapter.md) сохраняет вывод до возврата инструмента и в локальной проверке не рвёт цепочку code-mode. Используйте его для ожидаемо большого или шумного вывода: короткий ответ может стать длиннее после обёртки. Прототип включается вручную, работает на POSIX и пока не входит в установленный плагин.

В [пилоте на трёх парах с закреплённой версией](docs/measurements/2026-09-24-explicit-adapter-pilot.md) проверки прошли в обеих руках, а суммарных токенов с адаптером стало меньше. При этом общее время выросло; результаты отдельных задач различались, устойчивую экономию пилот не доказал.

Запустите hook-скрипт с тем же каталогом `PLUGIN_DATA`, который виден в окружении установленного хука:

```bash
PLUGIN_DATA=/path/to/your/sol-codex-data \
  python3 /path/to/installed/sol-codex/scripts/sol_hook.py --report
```

Команда `--report` печатает JSON только с агрегированными счётчиками байтов. Имя marketplace влияет на пути кеша и данных, поэтому берите разрешённые пути из `/hooks`, а не угадывайте. Формулы и ограничения описаны в [методике](docs/savings.md).

В [историческом локальном срезе](docs/savings.md) 355 событий содержали 8 158 596 байт извлечённого исходного текста и вернули 735 540 байт квитанций: арифметическая разница составила 7 423 056 байт (90,98%). Это не измерение входа модели, токенов, денег, квоты, времени или качества задач. Срез сделан до поддержки строковых результатов и изменения доставки в 0.1.9; он включает только вывод, прошедший порог размера и проверку на уменьшение объёма, а 338 старых событий не имеют привязки к модели. Результаты SoL-Pi к этому плагину неприменимы.

## Безопасность и ограничения

Полные локальные артефакты могут содержать ключи, исходный код и персональные данные. Плагин никуда их не отправляет. На macOS/Linux он выставляет приватные права, а на Windows файлы наследуют ACL NTFS; пользователь или процесс с доступом к учётной записи всё равно сможет их прочитать. Перед работой с чувствительными данными прочитайте [docs/security.md](docs/security.md).

На Windows плагин использует `msvcrt` для блокировки файлов и наследует права NTFS для локальных артефактов. Оборачивание Bash-команд проверки и тесты Unix-сигналов применимы только на macOS и Linux; в Windows проверка может использовать структурированный код завершения `exec_command`. Ошибки хуков обрабатываются fail-open, чтобы не уронить Codex; при деградации контроль verification debt становится рекомендательным. Разбор конфликтов хуков, trust-запросов, старого cachebuster и отсутствующего каталога данных есть в [docs/troubleshooting.md](docs/troubleshooting.md).

## Удаление

```bash
codex plugin remove sol-codex@sol-codex
```

Удаление плагина не удаляет локальные артефакты. Подтверждённый каталог `PLUGIN_DATA` удаляется отдельно. Удаление marketplace и безопасная очистка описаны в [инструкции](docs/installation.md).
