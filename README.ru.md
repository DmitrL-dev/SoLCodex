# SoL Codex

SoL Codex — локальный плагин для Codex Desktop. Он сохраняет полный вывод крупных инструментальных вызовов на диске, возвращает модели ограниченную редактированную квитанцию и отслеживает, были ли изменения кода проверены. Это независимая адаптация идей SoL для системы хуков Codex.

Плагин меняет вывод инструмента, видимый модели, а в режиме `bypassPermissions` оборачивает распознанные команды проверки для записи их кода завершения. Он не выбирает модель, не запускает compaction, не вызывает другую модель и не обещает изменений расхода токенов, стоимости, квоты или качества ответа.

## Быстрый старт

Нужны Codex с поддержкой плагинов и хуков и Python 3.9 или новее. Эта локальная Windows-сборка запускает хуки через `C:/Python311/python.exe`; официальный релиз рассчитан на macOS и Linux. Контракт хуков проверен авторами на Codex `0.155.0-alpha.9.2`.

```bash
codex plugin marketplace add DmitrL-dev/SoLCodex
codex plugin add sol-codex@sol-codex
```

Откройте `/hooks`, проверьте разрешённые команды и подтвердите доверие к плагину, когда Codex запросит его. Затем создайте новую задачу: lifecycle-хуки подхватываются при её старте. Обновление, переустановка и особенности кеша описаны в [инструкции](docs/installation.md).

## Что делает плагин

- `PostToolUse` обрабатывает результаты shell-команд и патчей. Подходящий вывод больше 12 KiB сохраняется без изменений в `PLUGIN_DATA`; для `gpt-6-astra` порог равен 4 KiB.
- Модель получает ограниченную квитанцию со статусом (либо `unknown`), хешами, диагностическими строками и коротким preview. Редактирование секретов в квитанции работает по известным шаблонам; полный локальный артефакт не редактируется.
- Успешное изменение кода создаёт verification debt. Распознанная команда снимает его только если соответствующий `PreToolUse` сработал после последнего изменения кода, а структурированный статус или приватный status-файл подтвердил код завершения 0.
- `PreCompact`, `PostCompact` и `SessionStart` сохраняют напоминание после compaction. `Stop` предупреждает о невыполненной или неуспешной проверке, не блокируя ответ; агент обязан честно сообщить статус проверок.
- По каждой модели считаются агрегированные байты исходного вывода, квитанции и разницы. Это не измерение токенов, стоимости, квоты, задержки или качества.

Строковый результат `PostToolUse` можно упаковать, если до хука дошло достаточно байтов, но квитанция показывает `exit_code=unknown`, если статус не пришёл из sidecar проверки. `PreToolUse` записывает поколение изменений кода для распознанной проверки. Только в режиме `bypassPermissions` он дополнительно оборачивает распознанные Bash-проверки для фиксации статуса; в режимах с подтверждениями он не переписывает команды и не выдаёт разрешения автоматически. Структурированный результат может передать статус напрямую. В code-mode хост может обрезать вывод до вызова хука; плагин восстановить его не может.

Схема и точная последовательность событий приведены в [описании архитектуры](docs/architecture.md).

## Настройка порогов

Переменные нужно задать до запуска Codex:

```bash
export SOL_CODEX_ASTRA_PACK_THRESHOLD_BYTES=4096
export SOL_CODEX_PACK_THRESHOLD_BYTES=12288
```

`SOL_CODEX_ASTRA_PACK_THRESHOLD_BYTES` действует только для уже активной `gpt-6-astra`. `SOL_CODEX_PACK_THRESHOLD_BYTES` — глобальное переопределение с более высоким приоритетом. Значения задаются в байтах и ограничиваются снизу числом 256. Плагин не выбирает модель: Astra-профиль включается только когда Codex уже передал `gpt-6-astra` как текущую модель.

## Отчёт

Запустите hook-скрипт с тем же каталогом `PLUGIN_DATA`, который виден в окружении установленного хука:

```bash
PLUGIN_DATA=/path/to/your/sol-codex-data \
  python3 /path/to/installed/sol-codex/scripts/sol_hook.py --report
```

Команда `--report` печатает JSON только с агрегированными счётчиками байтов. Имя marketplace влияет на пути кеша и данных, поэтому берите разрешённые пути из `/hooks`, а не угадывайте. Формулы и ограничения описаны в [методике](docs/savings.md).

В [историческом локальном срезе](docs/savings.md) 355 упакованных событий содержали 8 158 596 байт исходного вывода и вернули 735 540 байт квитанций: на 7 423 056 меньше сериализованных байт, видимых модели (90,98%), только для этих событий. Это локальный учёт байтов, а не измеренная экономия токенов, денег, квоты или времени; сохранение качества задач он тоже не доказывает. Срез сделан до поддержки упаковки строковых результатов, включает только вывод, прошедший действующий порог размера и проверку на уменьшение объёма, а 338 старых событий не имеют привязки к модели. Результаты SoL-Pi к этому плагину неприменимы.

## Безопасность и ограничения

Полные локальные артефакты могут содержать ключи, исходный код и персональные данные. Плагин выставляет приватные права и никуда их не отправляет, но пользователь или процесс с доступом к учётной записи всё равно сможет их прочитать. Перед работой с чувствительными данными прочитайте [docs/security.md](docs/security.md).

Эта локальная Windows-сборка использует `msvcrt` для блокировки файлов и наследует права NTFS для локальных артефактов. Оборачивание Bash-команд проверки и тесты Unix-сигналов применимы только на macOS и Linux; в Windows проверка может использовать структурированный код завершения `exec_command`. Ошибки хуков обрабатываются fail-open, чтобы не уронить Codex; при деградации контроль verification debt становится рекомендательным. Разбор конфликтов хуков, trust-запросов, старого cachebuster и отсутствующего каталога данных есть в [docs/troubleshooting.md](docs/troubleshooting.md).

## Удаление

```bash
codex plugin remove sol-codex@sol-codex
```

Удаление плагина не удаляет локальные артефакты. Подтверждённый каталог `PLUGIN_DATA` удаляется отдельно. Удаление marketplace и безопасная очистка описаны в [инструкции](docs/installation.md).
